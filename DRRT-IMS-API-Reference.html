DRRT-IMS API
REST API powering the DRRT Information Management System. Built on Laravel with Sanctum token authentication.

User Roles

Access to certain endpoints is restricted by the authenticated user's role.

Member
Registered organization member. Can view their own data and submit attendance.
Officer
Can manage applications, events, and attendance records for all members.
Adviser
Highest role. Approves events, removes members, sees all incident reports.

Authentication

  • No Account — no token needed.
  • Member — requires a Bearer token (any logged-in user) in the Authorization header.
  • Officer / Adviser — an extra badge marking the role the endpoint is meant for.
  • Get a token from POST /login or POST /register.

Example header:


Authorization: Bearer 1|abc123yourtoken...

Response Format

  • All responses are JSON.
  • Creates return 201.
  • Reads and updates return 200.
  • Deletes return 200, or 204 with no body.
  • Validation errors return 422 with an errors object.
  • Permission errors return 403 with a message.
Authentication
Registration, login, logout, profile management, and email-based verification flows.
POST /send-verification-code No Account ▶
Description

Sends a 6-digit verification code to the given email address. Required before registering a new account. The code expires after 10 minutes.

Request Body
FieldTypeNotes
emailstringMust be unique — not already registered required
Response 200
{ "message": "Verification code sent." }
Returns 500 with a message if the email could not be sent.
POST /register No Account ▶
Description

Creates a new member account. The applicant must have an approved membership application and a valid verification code sent to their email first.

Request Body
FieldTypeNotes
namestringDisplay name (max 255) required
emailstringMust be unique required
passwordstringMin 8 characters required
codestring6-digit verification code from email required
membership_application_idintegerMust exist and be in status approved_need_register required
Response 201
{ "user": { ...user object }, "token": "1|abc..." }
On success the application's status becomes approved_member_now and is linked to the new account. Returns 422 if the code is invalid or expired, and 403 if the application is not approved_need_register.

DELETE /membership-applications/{id} MemberOfficer ▶
Description

Deletes only the application record. The linked user account (if any) is not removed.

Response 200
{ "application_id": "5" }
DELETE /membership-applications/{id}/member MemberAdviser ▶
Description

Fully removes a member: deletes their application, their account, all their auth tokens, and their own attendance records. Attendance and application records they touched as a recorder or reviewer are kept, with the recorder/reviewer set to null.

Response 200
{ "application_id": "5" }
Only the adviser role can call this endpoint. Any other role gets 403.

Query Parameter

Updates an event's details. Same fields as POST /events — only the provided fields are updated. Does not change pending_approval.

Attendance
Record and manage event attendance. Members may self-report; officers record on behalf of others and handle correction requests.
GET /attendances Member ▶
Description

Without ?all: returns only the authenticated user's own attendance records. With ?all=1: returns all members' records (graduated members excluded), each with their recorder info — intended for officers.

Allows a member to flag their own attendance record for an officer to correct. Sets correction_requested: true.
